# Features

The feature registry for Mimori. Every product capability is tracked here with its true status.

## Status definitions

| Status | Meaning |
| ------ | ------- |
| `PLANNED` | Agreed as needed, not started. |
| `IN_PROGRESS` | Actively being built; not usable end to end. |
| `IMPLEMENTED` | Code exists and works, but has not been verified against its requirements. |
| `VERIFIED` | Built **and** checked — the behaviour was exercised and confirmed. |
| `BLOCKED` | Cannot proceed because of an unresolved dependency or decision. |
| `DEPRECATED` | Still in the codebase but no longer supported; scheduled for removal. |

Use only one status per feature. `VERIFIED` is the only status that means "done"; never mark something `VERIFIED` without having tested it.

## Current implementation status

The user-facing surface is the **homepage** (`HOME-1`…`HOME-6`, `WIDGET-1`), the **gallery** (`HOME-3`) with photo uploads (`MEDIA-1`), **collections** (`PHOTO-2`) and the **photobooth** (`PHOTO-5`…`PHOTO-9`), all reached through the shared navigation (`NAV-1`). The Photo Booth can be configured, photographed, decorated, saved to the Gallery, downloaded, reopened from **Our Saved Photobooths** and edited again without another shoot (`PHOTO-4`, `PHOTO-8`, `PHOTO-9`).

What exists today:

- A Next.js 16.4.3 + TypeScript application scaffold with App Router.
- The Romantic Scrapbook homepage (`/`): hero carousel, the customizable widget desktop and the "Our Love Story" band, built from the supplied photos.
- The gallery page (`/gallery`): a scrapbook title band and the polaroid photo grid with a photo viewer that opens any photo at full size. The `Photo` table is the **only** image source; an empty gallery shows its empty state and an unreachable database shows an error, never bundled pictures.
- The collections pages (`/collections`, `/collections/[id]`): pinned and manual collections of gallery photos with search, sorting, covers, pinning, adding, removing and moving photos, renaming and deletion. Recently Added is the gallery itself, newest first by `createdAt`; with no photos it shows colourful empty slots.
- The photobooth (`/photo-booth`): **Our Saved Photobooths** lists every saved session with its print thumbnail and opens any of them straight into the editor; the setup below chooses photo count, strip/collage shape and one of six borders through scrapbook selection cards with a live SVG print; **Start Photobooth** opens the camera, counts down and shoots the chosen number of photographs, allows switching cameras and retaking one or all, and reviews them in the print's real geometry. The editor swaps borders and paper, adds draggable stickers, writes a caption and date and adjusts spacing and frame thickness while showing the live print; **Finish editing** renders the exact 1600px JPEG, which can be saved to the Gallery (captures become `PHOTO_BOOTH` photos, the page a `GALLERY` photo) or downloaded. A saved booth's next save updates that same session, keeping its photographs.
- APIs for widgets (`/api/widgets`, `/api/widgets/[id]`), collections (`/api/collections`, `/api/collections/[id]`, `/api/collections/move`), photo uploads (`/api/photos/upload`), the gallery's photo list (`/api/gallery`) and the hero carousel (`/api/hero`) that store shared state in PostgreSQL through Prisma.
- Basic project tooling (Tailwind CSS, ESLint) and zero-dependency Node tests for the ordering rules.
- A design-system foundation (colour, theme, typography tokens).
- A Prisma 7.10.1 data model — four global models, one applied migration, no data access code ([D-013](DECISIONS.md)).
- An installable Progressive Web App: web app manifest (`/manifest.webmanifest`, standalone, light-mode pink), 192/512 and maskable icons, Apple touch icon, a service worker that caches only static assets and an offline page, and an install prompt (native on Chromium, Share → Add to Home Screen steps on iOS Safari). Its mobile viewport is fixed-scale — no pinch or double-tap zoom (PWA-1). Details: [D-054](DECISIONS.md), [D-056](DECISIONS.md), [ISSUE-029](KNOWN_ISSUES.md), [ISSUE-030](KNOWN_ISSUES.md).
- This documentation system.

What does **not** exist: no authentication (deliberately — [D-013](DECISIONS.md)), no undo or trash for a deleted photo (MEDIA-2 is permanent — [ISSUE-027](KNOWN_ISSUES.md)), and no offline data: the PWA's offline page only states the app is unreachable, and uploads, gallery, collections and the photo booth require a connection. Push notifications and background sync are not implemented. The Gallery is the single image source ([D-033](DECISIONS.md)): the gallery page, the eight hero slots, collections, widgets and Recently Added all read `Photo` rows, so the first thing a new installation asks for is an upload, and nothing anywhere falls back to `public/couple-images`.

All five photobooth phases are complete: an unsaved session still lives only in the tab, but a saved booth can be reopened and edited from the library ([ISSUE-021](KNOWN_ISSUES.md)).
